# 신규 글 작성

에이전트와 실제로 설치하고 삽질한 대화를 그대로 블로그 글로 만든다.
대화 → 목차 협의 → 초안 → Notion 페이지 생성 → 동기화까지가 한 흐름이다.

주제가 인자로 왔으면 그대로 쓴다. 없으면 묻는다. 그다음 `temp/{주제}/` 작업 공간을 만들어
경로를 알리고 지금이 1단계임을 말한 뒤, 평소처럼 대화하면서 로그를 쌓는다.

---

## 원칙

**대화가 취재다.** 글의 재료는 검색 결과가 아니라 이 세션에서 실제로 실행한 명령과
거기서 난 오류다. 확인하지 않은 절차는 글에 넣지 않는다. 넣어야 한다면 "확인하지 않았다" 고
본문에 밝힌다.

**실습은 사람이 한다.** 설치·기동·설정 명령을 에이전트가 직접 실행하지 않는다.
글은 사람이 자기 환경에서 겪은 일의 회고다. 에이전트가 대신 돌리면 그 환경이 글에서 사라진다.
명령과 파일을 만들어 건네고, 사람이 실행한 출력을 받아 기록한다.

읽기는 해도 된다. 버전 확인, 포트 점유 확인, 파일 읽기처럼 상태를 바꾸지 않는 것은 괜찮다.
경계가 애매하면 묻는다.

**혼자 다음 단계로 넘어가지 않는다.** 목차와 초안은 사람이 승인해야 다음으로 간다.
Notion 페이지 생성은 초안 승인 뒤에만 한다.

**Notion 이 원본이다.** 초안이 아무리 완성돼 있어도 `content/posts/**/index.md` 에
직접 쓰지 않는다. Notion 에 만들고 동기화한다.

---

## 단계

### 1단계 · 실습과 기록

사람이 주제를 던지고 설치·설정을 물어보는 구간이다. 답하면서 동시에 기록한다.

글 하나가 `temp/{주제}/` 디렉터리 하나를 쓴다. 주제는 짧은 영문 한 단어로 잡는다
(`garage`, `sops`). 최종 `content/posts/{카테고리}/{slug}/` 와 같은 번들 구조라
나중에 눈으로 대조하기 쉽다.

```
temp/garage/
├── index.md              # 작업 로그. 3단계에서 이 파일이 초안이 된다
├── docker-compose.yml    # 실습에서 만든 파일을 옆에 둔다
└── garage.toml
```

git 이 무시하지만 사람이 에디터에서 열어보는 자리다. 경로를 알리고 시작한다.
대표 이미지 후보가 떨어지는 `tmp/` 와 헷갈리지 않는다.

`index.md` 에 남길 것:

- 환경 - OS, 버전, 하드웨어. 재현에 필요한 전제
- 실행한 명령과 실제 출력. 요약하지 말고 붙여넣는다
- 막힌 지점과 해결책. **이게 글의 핵심이다.** 공식 문서에 없는 것만 사람이 검색한다
- 사람이 내린 결정과 그 이유. "왜 A 대신 B 를 골랐나"

컨텍스트가 길어지면 요약되므로 로그 파일에 그때그때 남긴다. 나중에 복원할 수 없다.

사람이 "이제 글 쓰자" 라고 하면 2단계로 간다.

### 2단계 · 목차 협의

바로 본문을 쓰지 않는다. 먼저 뼈대를 제안하고 합의한다. 제안에 담을 것:

- **제목 후보 2~3개** - 한글 약 16px · ASCII 약 8px 기준 600px 안
- **요약 1~2문장** - 같은 기준 920px 안. 사람들이 복사해 검색하는 문자열
  (`InvalidAccessKeyId` 같은 것)은 맨 앞에 둔다
- **slug** - 영문 kebab-case. 핵심 키워드가 앞
- **카테고리 1개** · **태그 3~6개** - 아래 "Notion 프로퍼티" 의 기존 값에서 고른다
- **목차** - H2 단위로. 각 절마다 "무엇을 다루는지" 한 줄씩
- **넣지 않을 것** - 로그에는 있지만 글에서 뺄 내용과 그 이유

사람이 순서를 바꾸거나 절을 빼면 그대로 반영한다. 승인 없이 3단계로 가지 않는다.

### 3단계 · 초안 작성

1단계에서 쌓은 `temp/{주제}/index.md` 를 초안 전문으로 덮어쓴다. 로그는 역할을 다했다.
보여주고 고친다.

문체는 [CLAUDE.md](../../../CLAUDE.md) 의 "글 쓰기" 를 따른다. 특히:

- **절을 쉼표로 잇지 않는다.** 문장을 끊는다. 쉼표로 이어 붙인 긴 문장은 AI 티가 난다
- 마무리를 같은 리듬의 불릿으로 채우지 않는다. 산문으로 흐름을 만든다
- 코드 블록에 언어를 명시한다. 명령과 출력은 분리한다
- **코드 블록 안에 한글 주석을 쓰지 않는다.** 꼭 필요한 주석만 영어로 짧게 단다.
  포트 옆의 `# S3 API` 정도는 되고, 한 줄로 설명할 수 있는 건 전부 본문 산문으로 뺀다.
  이유는 두 가지다. 번역본(en·ja)이 두 개 더 생기는데 주석이 한글이면 블록이 언어별로
  갈라진다. 그리고 주석이 붙을수록 독자가 복사해 쓸 설정이 길어진다
- **예시 식별자에 한글을 쓰지 않는다.** 버킷명·경로·키·변수명은 `mybucket` 처럼 영문으로 둔다.
  한글 식별자는 URL 인코딩 이야기와 섞여 독자를 헷갈리게 하고 번역본에서 깨진다
- **공식 문서의 예시 값을 바꾸지 않는다.** 설정 값·경로·이름은 문서와 같게 쓴다.
  임의로 지어내면 독자가 무엇이 규약이고 무엇이 예시인지 구분하지 못한다.
  임의값이라는 사실은 문장으로 짚고, 예시 자체는 문서와 맞춘다
- 상호 링크는 Notion 페이지 멘션으로 건다. **표 안에 넣지 않는다.** 표 안의 멘션은
  동기화하면 "Untitled" 로 깨진다. 안내 문단 아래 불릿으로 놓는 것이 이 블로그 관례다

H1 은 쓰지 않는다. 제목은 Notion 의 `제목` 프로퍼티가 된다. 본문은 H2 부터 시작한다.

### 4단계 · Notion 페이지 생성

초안을 승인받은 뒤에만 한다.

**먼저 POST_ID 를 정한다.** `collection://2fd22a0f-7e83-814c-9f88-000b7bdd1d4a` 를
모든 상태에 걸쳐 조회해 최댓값 + 1 을 쓴다. 로컬 `content/posts/**/index.md` 의 `id:` 로
구하면 안 된다. 초안·작성중 상태로 이미 POST_ID 를 가진 페이지가 로컬에 없어서 번호가 겹친다.
`AUTO_ID` 는 별개의 자동 증가값이라 POST_ID 가 아니다.

`notion-create-pages` 로 POST_DB 아래에 만든다.

| 프로퍼티 | 타입 | 값 |
| --- | --- | --- |
| `제목` | title | 합의한 제목 |
| `요약` | text | 합의한 요약 |
| `slug` | text | 합의한 slug |
| `POST_ID` | text | 위에서 구한 max + 1 |
| `카테고리` | select | Git · Database · IDE · Docker · Develop · AI · Infra · OS · Cloud · Etc · Web · Hugo · SSG · Networking · DevOps · IoT · Security |
| `태그` | multi_select | 기존 태그 우선. 새로 만들 땐 사람에게 먼저 묻는다 |
| `상태` | status | `초안` 으로 둔다. 사람이 읽고 `발행 요청` 으로 바꾼다 |
| `AI_번역` | checkbox | 기본 `true`. 한국 한정 서비스를 다루면 `false` |
| `toc` | checkbox | `true` |
| `생성일` | date | 오늘 |

`발행일` · `발행 URL` · `발행 결과` · 링크드인 칸은 건드리지 않는다. 파이프라인이 채운다.

만든 뒤 페이지 URL 을 사람에게 준다.

### 5단계 · 대표 이미지와 동기화

대표 이미지는 `hans-blog` MCP 의 `generate_featured_image` 를 `pageId` · `caption` 과 함께
부른다. SVG 를 직접 그리지 않는다. 자세한 건 [generate-featured-image.md](../../../prompts/generate-featured-image.md).

사람이 Notion 에서 읽고 상태를 `발행 요청` 으로 바꾼 뒤 동기화한다.

**발행 뒤에 글을 고쳤다면 상태를 다시 `발행 요청` 으로 돌린다.** `발행 완료` 는 동기화
대상에서 빠진다. 오타 하나를 고쳐도 상태를 되돌려야 반영된다.

```bash
node src/NotionCli.mjs page sync {page_id}      # 이 글만
node src/NotionCli.mjs database sync            # 발행 요청 전체
```

`⏭️ Skipped (not modified)` 가 뜨는데 방금 고친 게 확실하면 믿지 않는다.
`last_edited_time` 이 분 단위라 같은 분 안의 두 번째 수정을 놓친다.
해당 디렉터리의 `notion_*.json` 을 지우고 다시 동기화하면 강제로 다시 만든다.

동기화 결과 `content/posts/{카테고리}/{slug}/index.md` 를 열어 확인한다. 볼 것:

- front matter 의 `id` · `slug` · `description` 이 비어 있지 않은가
- 코드 블록의 언어와 들여쓰기가 살아 있는가
- 상호 링크가 `../{POST_ID}-{slug}/` 로 바뀌었는가. `Untitled` 가 있으면 표 안의 멘션이다
- 대표 이미지 경로와 alt 가 맞는가

번역은 `AI_번역` 이 `true` 일 때만, [translate-database-sync.md](../../../prompts/translate-database-sync.md) 를
따라 별도로 돌린다.

## 체크리스트

- 글에 들어간 명령을 이 세션에서 실제로 실행했는가
- 목차와 초안을 사람이 승인했는가
- POST_ID 를 Notion DB 전체에서 구했는가
- 절을 쉼표로 이어 붙인 문장이 남아 있지 않은가
- 마무리가 불릿 나열로 끝나지 않는가
- 표 안에 페이지 멘션을 넣지 않았는가
- `content/posts/**/index.md` 를 직접 고치지 않았는가
